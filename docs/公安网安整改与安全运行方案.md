# 得胜服务通公安网安整改与安全运行方案

更新时间：2026-08-27
适用范围：得胜服务通微信小程序、Web 管理后台、后端 API、数据库、对象存储及运维账号。

## 一、当前结论

1. 项目没有用户评论、帖子、私信、聊天室等公开互动功能，现有功能不构成“任意用户发布不良评论”的入口。以后也不得在未完成内容审核、实名追溯和应急处置设计前新增此类功能。
2. 用户规模只有约 1744 人并不代表不会被攻击。身份证、手机号、户籍名单和民政材料具有较高黑产价值，撞库、弱口令、密钥泄露、数据库误开放、Git 历史泄露和备份泄露都可能造成事故。
3. 本次整改后，后台页面、普通后台接口和导出文件只显示脱敏身份证号、手机号；业务表中的完整号码改为加密保存，检索和去重使用带密钥摘要。
4. 项目不能自行宣布已通过网络安全等级保护测评。建议由属地公安网安或有资质机构根据系统边界、部署形态和实际数据处理情况确定定级；在未取得正式意见前，按不低于等保二级常见控制要求准备账号、日志、备份、边界防护和应急材料。

## 二、已经落入代码的控制

- 身份证与手机号：数据库密文保存，页面/API/导出只返回掩码；后台不再提供“查看完整号码”权限。
- 历史业务数据：`backend/scripts/migrate_sensitive_business_data.py` 可幂等迁移诉求、政务办件、培训和志愿报名中的明文号码，并将身份证脱敏副本统一为“仅前 6 位可见”、清空单独保存的后 4 位；脚本不打印任何个人信息。
- 后台认证：密码至少 12 位并包含至少两类字符；生产环境强制 TOTP 双因素认证；恢复码只展示一次并仅保存哈希；重置密码后强制重新登录/设置 MFA。
- 后台网络：可用 `ADMIN_ALLOWED_IP_CIDRS` 限制村委会固定公网 IP 或可信 VPN 出口；未配置时生产检查会告警。
- 审计与告警：登录失败、IP 限流、账号锁定、MFA 失败、恢复码使用、后台来源 IP 拒绝、批量查看和脱敏导出均写入审计日志或 `security_alert` 运行日志。
- 备份：`backend/scripts/secure_database_backup.py` 生成独立密钥加密、带完整性校验的备份，并支持验证与 SQLite 隔离恢复演练；明文临时文件只存在于权限受限的临时目录。
- 代码历史：含真实户籍名单的 Git 对象必须从全部分支和标签历史中清除；清理后旧克隆、旧压缩包和旧构建机副本仍需单独销毁或隔离。

## 三、上线前必须完成的现场配置

1. 生成三把互不相同的 32 字节随机密钥，分别配置 `ID_CARD_AES_KEY_HEX`、`PHONE_AES_KEY_HEX`、`BACKUP_ENCRYPTION_KEY_HEX`。密钥只能放在云平台密钥/环境变量管理中，不得写入代码、聊天、工单或截图。
2. 配置 `ADMIN_MFA_REQUIRED=1`。由每位管理员本人使用验证器 App 扫描 TOTP，恢复码打印后密封保管，不得存入共享群聊。
3. 能取得固定出口 IP 时配置 `ADMIN_ALLOWED_IP_CIDRS`；没有固定 IP 时，先通过可信 VPN/零信任入口形成固定出口再配置。反向代理必须覆盖客户端传入的 `X-Forwarded-For`/`X-Real-IP`，不能原样信任互联网请求头。
4. 数据库只允许云托管服务所在私网访问；关闭公网直连；使用最小权限业务账号和独立备份账号；数据库、对象存储、云平台管理员账号均启用 MFA。
5. 对象存储保持私有读写，不得把身份证、户口簿、银行卡、病历等材料设置为公开链接；签名链接保持短时有效。
6. 运行敏感数据迁移前先做一次加密备份并验证；迁移后用只统计数量的 SQL/脚本确认业务明文字段已清空或只剩掩码。
7. 上传新后端和 Web 后台，完成管理员改密/MFA、脱敏页面、办件提交、回复材料、报名和导出回归测试后再正式切流。

## 四、日志告警规则

云托管日志平台以 `security_alert` 为检索词建立告警，通知至少两名负责人。日志不得记录身份证号、手机号、密码、令牌、MFA 密钥、恢复码、数据库连接串或文件正文。

| 事件 | 建议阈值 | 处置 |
| --- | --- | --- |
| `admin_ip_denied` | 5 分钟 ≥ 3 次 | 核对来源，必要时封禁 IP、检查代理头配置 |
| `admin_login_ip_rate_limited` | 任意 1 次 | 按账号入侵事件处理 |
| `admin_mfa_failed` | 10 分钟 ≥ 3 次 | 锁定账号、联系本人、核查登录 IP |
| `admin_mfa_recovery_code_used` | 任意 1 次 | 联系本人确认并立即重新生成 MFA 恢复码 |
| `admin_bulk_request_view` | 任意 1 次 | 核对是否为授权的集中办理操作 |
| `admin_bulk_identity_view` | 任意 1 次 | 核对是否为授权业务操作 |
| `admin_masked_identity_export` | 任意 1 次 | 审核导出用途、接收人和删除时间 |

建议审计日志在线保存不少于 180 天，安全告警日志根据属地要求和平台能力延长保存；实际期限由村委会与公安网安确认。

## 五、备份与恢复

- 目标：数据库每日加密备份；至少保留 30 个日备份和 12 个月备份；数据库与备份密钥分开保管；备份桶启用私有访问、版本控制和防误删策略。
- 恢复指标建议：核心服务 RTO 4 小时，RPO 24 小时。经现场评估后可再收紧。
- 每次备份生成后立即执行 `verify`；每季度至少一次恢复到隔离环境，禁止直接覆盖生产库。

示例：

```bash
cd backend
.venv/bin/python scripts/secure_database_backup.py backup --output-dir /受控备份目录
.venv/bin/python scripts/secure_database_backup.py verify /受控备份目录/某个备份.dscbk
.venv/bin/python scripts/secure_database_backup.py restore-sqlite /受控备份目录/某个备份.dscbk --target /隔离目录/restore-test.db
```

生产 MySQL 的恢复演练应恢复到新建的隔离数据库实例，再运行 `scripts/verify_mysql_migration.py` 和业务回归测试。当前脚本不会自动覆盖生产 MySQL，避免误操作。

## 六、安全事件应急步骤

### 0—15 分钟：止损

1. 由安全负责人宣布进入事件状态，记录发现时间、告警内容和操作人。
2. 在云平台暂停后台公网入口或把 `ADMIN_ALLOWED_IP_CIDRS` 临时收紧到应急出口；不要先删除日志。
3. 禁用可疑管理员账号，撤销全部后台会话，轮换后台密码、数据库密码、对象存储密钥、微信密钥和应用加密密钥。
4. 对疑似泄露的数据库、日志、构建物、Git 仓库和对象存储做只读快照，保存证据哈希。

### 15—60 分钟：判断范围

1. 核对异常登录 IP、时间、账号、导出记录、对象存储访问、数据库查询和云平台操作日志。
2. 判断是否涉及身份证、手机号、户籍表、银行卡/病历图片、管理员凭证或加密密钥。
3. 区分“攻击尝试”“账号失陷”“数据被读取”“数据被导出/外传”，不得在证据不足时宣称没有泄露。

### 1—24 小时：恢复与报告

1. 从已验证备份恢复到隔离环境，完成完整性和业务回归后再切换服务。
2. 由村委会负责人决定并执行向属地公安网安、网信或其他主管部门的报告；发生或可能发生个人信息泄露、篡改、丢失时，依法采取补救、评估影响并履行告知/报告义务。
3. 对受影响人员的通知不得包含他人的个人信息，应说明事件类型、可能影响、已采取措施、自我保护建议和联系方式。

### 事件结束后

形成事件报告：时间线、根因、受影响数据范围、处置动作、证据位置、通知与报告记录、整改负责人和完成期限。未经负责人批准不得销毁证据。
