# 得胜服务通

面向湖南省平江县上塔市镇得胜村村民的公益服务微信小程序，配套村干部使用的 Web 管理后台。

项目把村务通知、村务公开、便民办事集中到一个小程序里：村民在手机上就能看通知、查政策、提交办事申请、查看办理结果；村干部在后台统一发布内容、处理办件。项目不以盈利为目的，服务全村 9 个村民小组、538 户、1744 名村民。

> 本仓库是 v1.1.0 网安整改版本的**脱敏代码副本**，从一次干净的初始提交开始，不含原项目的 Git 历史，也不含生产数据库、户籍名册、真实环境配置和村民材料。小程序 AppID、联系电话、部署地址等已替换为占位内容，真实村委会印章以项目图标代替，不能直接用于部署生产环境。

## 功能

### 村民端

| 页面 | 功能 | 是否需要登录 |
|---|---|---|
| 首页 | 置顶通知、村委会服务电话、历史通知、第三方政务服务入口 | 否 |
| 办理 | 开具证明、低保申请、特困认证、随手拍 / 服务需求 / 问题投诉、村民建议、就业培训报名、志愿服务报名 | 浏览不需要，提交需实名认证 |
| 公开 | 村情简介、人口与党员等公开指标、村部图片 | 否 |
| 好物 | 本村特色产品介绍（平江烟茶、乡间腊肉、得胜黄鳝面等），仅展示，不做交易 | 否 |
| 我的 | 个人资料、实名状态、办理记录、隐私政策、使用帮助 | 是 |

村民提交的申请、诉求、建议只有本人和后台工作人员能看到，不会展示给其他村民。

### 村委端

| 模块 | 功能 |
|---|---|
| 工作台 | 待处理诉求、办件数量、公开指标概览 |
| 内容发布 | 通知公告、数字公开、本地好物、就业培训、志愿活动 |
| 事务办理 | 证明、低保、特困、随手拍等办件的受理、回复、驳回和结果回传 |
| 建议收件箱 | 查看村民建议 |
| 村民数据 | 检索实名村民、导出脱敏名册 |
| 账号与审计 | 干部授权、后台账号与角色、操作审计日志 |

后台分为超级管理员、村干部、只读协办三种角色，账号只授予本村两委干部和镇级业务人员。

## 安全与隐私设计

2026 年 9 月，项目按公安机关网安部门的检查意见完成了一轮安全整改。当前版本的主要设计：

- **没有公开互动功能**：系统里没有评论、发帖、私信、聊天。所有公开内容只来自村委会后台发布，即使村民账号被盗，也无法通过本系统向他人发布任何内容。
- **身份证与手机号加密存储**：完整号码使用 AES-256-CBC 加密，附 HMAC 完整性校验，数据库中不存明文。
- **不可逆的身份比对**：实名认证用「姓名 + 身份证 HMAC」比对户籍白名单。HMAC 使用独立密钥并按用途派生子密钥，即使数据库泄露，也无法通过枚举还原身份证号。户籍白名单表不存身份证明文和密文。
- **后台脱敏展示**：身份证只显示前 6 位，手机号只显示前三后四；后台不具备查看完整身份证号的能力，导出的名册同样脱敏。
- **密钥隔离**：身份证加密、手机号加密、比对、备份加密四类密钥互相独立，只通过环境变量注入，不进代码库。
- **管理员账号安全**：Argon2id 存储密码、强制 TOTP 双因素认证、连续登录失败锁定、来源限流。
- **生产启动校验**：调试模式、模拟登录、弱密钥、缺少双因素等不安全配置会让服务直接拒绝启动。
- **其他**：接口限流与防重复提交、上传文件类型与文件头校验、操作审计日志、加密数据库备份工具。

以上描述的是代码层面的机制，不代表「绝无漏洞」，也不代表已通过第三方安全测评。

### 9 月整改前后对比

| 项目 | 整改前 | 整改后 |
|---|---|---|
| 通知互动 | 村民可在通知下提交回执，干部回复公开可见 | 功能整体下线，相关接口与数据表删除 |
| 身份比对 | 无盐 SHA-256，可被离线枚举 | 独立密钥、按用途派生的 HMAC-SHA256 |
| 身份证展示 | 保留末四位 | 只显示前 6 位 |
| 户籍白名单 | 同一份名册重复导入 | 重建为去重后的单一批次 |
| 后台登录 | 无强制双因素 | 强制 TOTP 双因素认证 |

安全运行与应急方案见 [docs/公安网安整改与安全运行方案.md](docs/公安网安整改与安全运行方案.md)，详细的修改记录见 [CHANGELOG.md](CHANGELOG.md)，上线流程见 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)。

## 本地开发

后端依赖见 `backend/requirements.txt`，管理后台依赖见 `web-admin/package.json`，配置模板见 `backend/.env.example` 和 `web-admin/.env.example`。

```bash
# 后端
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 管理后台
cd ../web-admin
npm ci
```

运行后端测试前，需要在 `backend/.env` 中配置本地开发用的随机密钥（可用 `openssl rand -hex 32` 生成），不要使用任何生产密钥：

```bash
cd backend
python -m unittest discover -s tests
```

小程序用微信开发者工具打开 `miniprogram/` 目录，并换成自己的 AppID 和后端地址。微信订阅通知模板 ID 不提供默认值，需通过 `WECHAT_NOTICE_SUBSCRIBE_TEMPLATE_ID` 自行配置。

测试代码中的身份证号使用以 `00` 开头的虚构行政区划，手机号使用 `100`、`101` 开头的虚构号码，口令只用于临时测试数据，均不对应任何真实人员。
